# Phase C1: text-first Action Agent

Status: real local-model and SDK evaluation ran, but C1 is **not ready for C2**: the pilot failed to solve any complete sample. This is a research baseline, not a submission-ready system.

## Isolation and sources

Branch `feature/lifemate-action-agent` starts at `d5d143e9574904923620000900be1bd52e651839` (ToolLoop research), reusing its lossless `ToolRegistry`, conservative schema validator, and localhost-only Ollama client. ASR and the existing worktrees are not changed. The local official SDK and catalog are external inputs and are not copied into the repository.

The inspected organizer SDK exposes `ToolEnv(split, question_id, root)`, `validate(name, arguments)` returning `ok` and `error`, `call(name, arguments)` returning the simulator result, `get_tool_calls()` returning the ordered recorded calls, and `get_state_hash()` returning its canonical state hash. SDK validation checks schema; execution may still fail. The SDK records attempted calls, including rejections, so the agent always validates first. It does not read simulator state, invoke `get_state`, reset an environment, or replay history. The SDK itself loads its own environment internally.

Organizer [general regulations](https://dl-challenge.zalo.ai/zalo-ai-challenge-regulations-en.pdf) contain competition-code disclosure restrictions (§8.2). The repository was checked as public. No C1 push should be made unless disclosure is resolved. We did not verify an official score formula, actual runtime limit, or exporter contract; the working 30-second budget and 16,384 context-token ceiling are configurable development limits, not confirmed official requirements.

## Runtime

The transcript (`audio_text` during evaluation), selected permitted context, up to 12 prior conversation entries and official observed results form the input. Only installed-app tool names from context plus the SDK's system missing-information tool are made available. The prompt uses catalog names, shortened descriptions, and parameter schemas with descriptive annotations removed; original registry schemas remain unchanged for deterministic checks. It excludes labels, expected states, other records and raw audio. The system prompt directs the model to use one call per step, find IDs using read tools, ask for missing fields or finish when unsupported. `finish` produces an empty recorded list if no call was executed, but correctness depends on the model and is not guaranteed.

Each proposal goes through installed-tool and conservative structural checks followed by official `env.validate`; only then is `env.call` invoked. The agent passes actual results into subsequent decisions and returns calls and hash exclusively from that same SDK instance. Model calls, repeated identical calls, retries, context length, output tokens and elapsed time are bounded. Identical calls are suppressed even if a future situation could make a repeated call meaningful. The reused validator covers types, required fields, enumerations, nesting, numeric limits and `x-one-of`; it does not fully implement `x-ref`, `x-match`, formats or all composite schema semantics. SDK validation is authoritative and errors are fed back to the model. Some conservative early checks may reject calls the SDK would allow. The timeout is a per-request socket limit plus checks between steps, not a hard process deadline. The backend can be replaced by providing a `generate_json` implementation with the same interface; the included backend is restricted to local Ollama, with deterministic decoding and no verifier or synthetic generation dependency.

## Evaluation and leakage boundaries

The read-only evaluator verifies the recorded dataset and catalog SHA-256 values, split counts, unique/disjoint IDs and dataset coverage. Its input reader skips over label values without decoding them; validation labels are made accessible only after all prediction attempts finish. It never selects examples by their labels. Test IDs are used only to validate disjoint coverage; test labels are never decoded. Split ID files are checked for integrity properties but are not individually hash-bound in the existing manifest, so assignment provenance depends on the existing local split files. The default paths assume the original project root holds `train/` and the sibling `toolloop-synthesis` worktree holds `outputs/toolloop/splits/`.

Artifacts are created only under ignored `outputs/agent/`, with no overwrite. Prediction rows contain SDK-recorded calls and hash; failure records never invent a hash. Results are local held-out diagnostics, not a validated official submission exporter. The scorer calculates ordered name and exact-call match, aligned argument match and multiset exact-call precision/recall/F1. It separately reports empty-gold and missing-info detection; empty-gold is not sufficient to establish out-of-scope semantics. It cannot infer dependencies from call counts. Gold `final_state` contains only changed applications, not a complete state, so a comparable full-state gold hash cannot be derived without forbidden additional state access. Hash-match, task completion and official score remain unavailable. Scenario categories and error categories without evidence are marked unknown. A failed inference may still produce valid SDK-authoritative empty calls and is included in structural metrics; errors are also counted separately.

## Verification

Commands executed from this worktree:

```
python -m unittest tests.test_action_agent_c1 tests.test_toolloop_ablation tests.test_toolloop_data tests.test_toolloop_feedback tests.test_toolloop_hardening tests.test_toolloop_synthesis -q
python -m scripts.evaluate_action_agent --dry-run
python -m scripts.evaluate_action_agent --sdk-smoke
python -m scripts.evaluate_action_agent --split val --limit 10 --seed 42 --output-dir outputs/agent/c1-pilot-final
```

76 selected mock/existing tests passed, including 9 new C1 unit tests. Full unittest discovery ran 77 tests but had one import error: the unrelated ASR test requires `numpy`, absent from this Python environment. The dry run found 155 validation IDs and 147 catalog tools, verifying dataset/catalog hashes. The separate real SDK smoke test initialized one official environment, validated and executed one safe `sys.ask_missing_info` call, recorded it, and obtained an SDK hash.

Actual local Qwen3-4B (`qwen3:4b-instruct-2507-q4_K_M`, seed 42, temperature 0) evaluated 10 random validation records, without selecting based on labels. Results: exact tool-name sequence 0/10, exact call sequence 0/10, precision/recall/F1 all 0, and aligned argument accuracy unavailable because no aligned names occurred at corresponding positions. Two records were single-call and eight multi-call; exact match was 0 in each group. There were 24 missing named actions and no extra named actions. No empty-gold examples were selected, so out-of-scope correctness is unavailable. Missing-info binary agreement was 9/10, but this is not evidence of correct missing-field handling. Of one actual SDK validation and execution, one passed validation and returned an apparent success; this tiny denominator is not task completion. There were 15 invalid model proposals, four invalid-retry-limit stops, one repeated-call stop and one prompt-budget model failure; no sample timed out. Mean latency was 2.42 s, p50 2.71 s, p95 3.43 s (nearest-rank); model time totaled 24.22 s and output tokens 1,497. One inference failed at the prompt budget even after compaction. Samples receiving SDK calls/hashes but suffering model failures are included in the 10; no sample initialization failed. Pilot output and detailed metrics remain ignored locally at `outputs/agent/c1-pilot-final/`.

Hardware observation: NVIDIA GeForce RTX 5060 Laptop GPU, 8,151 MiB total, 5,049 MiB in use at a single observation after the run; this is not peak usage or necessarily attributable to the model. A larger run was deliberately not attempted after the critical accuracy and prompt-budget failures. The pilot does not establish performance for dependency, out-of-scope, history-dependent, or all missing-info scenarios. The 30-second limit is not an officially verified constraint.
