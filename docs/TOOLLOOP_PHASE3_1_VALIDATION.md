## Code changes

The old byte-equals-token limit is removed. `OllamaClient` now estimates input conservatively as Unicode codepoint count for serialized messages and output schema times a configurable factor plus 128 tokens of fixed overhead; it separately reserves `num_predict` tokens. It also imposes an independent configurable HTTP payload byte cap. CLI options are `--token-estimate-factor` (default 1.0) and `--max-payload-bytes` (default 262144); `--context-length` remains capped at 16,384. Both successful request metadata and preflight rejection exceptions contain estimated input, output reserve, context and payload-byte diagnostics without prompt text. This is a heuristic, **not a tokenizer or a proof that a request fits**; Ollama/model behavior must still be checked. Vietnamese/nested schema fixtures demonstrate that requests above the former 3,328-byte limit can pass while clearly oversized inputs are rejected before network access.

For Stage 1, `simple` rejection stops immediately because its target/candidate set is invariant. A `multiple` sample can change only a supported distractor, only when all failed rubric checks concern distractor relevance. Seeded alternative ordering is deterministic, candidate signatures are tracked, and previously attempted sets are excluded. If the target itself is infeasible, feedback is not distractor-specific, or no alternative exists, the run stops with a reason. At most three refinements are allowed. Any upstream change causes query/call generation to be rerun; no previous downstream verdict is treated as current.

The existing literal argument-provenance policy is unchanged. A query containing a Vietnamese time phrase may correctly imply a normalized clock value without containing that value literally; such conversions can be falsely rejected. No broad temporal normalization or confidence-based acceptance was added. Ambiguous conversions stay unverified. No record receives automatic SFT approval.

Verified mode retains sequential inference and now checks Ollama `/api/ps` after unload requests and `keep_alive=0` calls, including alias/digest matching. Failure to confirm an unload is a technical error, not a semantic retry. OOM, timeout, unload failure and prompt-budget failures stop the pilot; model-load/unload overhead and peak VRAM remain unmeasured until a real experiment. This check cannot prevent another application from using the GPU.

## Paired ablation design

`scripts/ablate_toolloop_feedback.py` reads the existing train-only accessor and registry, selects a single fixed-seed scenario pool, freezes each Mode A candidate, and replays the same initial ground truth, query and calls in B (verify/filter, zero refinements) and C (verify/refine, up to three). The local manifest includes source train IDs, scenario IDs, targets, candidates, seeds, model digests/configurations and hashes. If an upstream value changes in C, the affected downstream stage is regenerated and its history marks it as new; the original candidate remains intact. If Mode A terminated before producing a complete initial candidate, B/C label it `not_evaluable` rather than inventing an output or silently dropping it. The verifier is invoked separately in B and C, so runtime/model nondeterminism can still affect judgments.

The harness caps the run at five scenarios, writes to a new ignored `outputs/toolloop/ablation/` directory without overwrite, stops on resource/transport failures and repeated malformed verifier outputs, and records partial outcomes. It separates raw local candidates, mode results, aggregate summary, limitations and a `not_reviewed` human worksheet. The worksheet covers tool and intent correctness, grounding, completeness, extra actions, Vietnamese naturalness, unsupported assumptions, and possible verifier false acceptances/rejections. **A verifier's own acceptance is not independent evidence of improvement**. No statistical significance or leaderboard accuracy follows from this small design.

Per-mode summaries expose scenario/status counts, structured/schema-valid rates, semantic acceptance where applicable, rejections and uncertainty, failure codes, refinement counts/recovery, generator/verifier tokens and latency where returned. Unmeasured load/unload overhead and peak GPU memory are recorded as unavailable. Full initial generation costs are attributed to A; B/C mark frozen outputs as reused rather than charging them as new generator requests. Independent quality remains unavailable until a human actually reviews the worksheet.
